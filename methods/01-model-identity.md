# 01 模型身份验证

目标：判断你买到的模型，是不是标牌上写的那个。改名冒充的常见形态：标牌是当期旗舰，底层实际路由到老一代型号或别家的低端模型——单价按旗舰收，质量低一档。

## 原则先行

- **自报不可信**。问「你是什么模型」得到的回答由 system prompt 和训练数据决定，可以被中转在注入 prompt 里直接指定。自报只记录，不作证据。
- **证据要来自能力与行为**：上下文长度、知识截止、解题质量、报错信息。这四样伪造成本最高。

## 方法一：知识截止探针

问一个只有新模型训练数据才可能覆盖的、具体且可核查的近期事实（例如某工具在某月的版本变化），再问一个老型号截止日期之前的对照题。

- 新题答出且细节对得上、旧题也对 → 与标牌代际一致
- 新题编造或明确说不知道、旧题正常 → 怀疑底层是老型号

注意：联网搜索能力会干扰此项，测试时关掉工具/联网（纯对话模式）再问。

## 方法二：长上下文回溯

1. 准备一段长文本（≥5 万字更稳妥，可用自己项目的文档、日志拼接）。
2. 在约 80% 位置埋入随机串，如 `校验串：violet-7392-kite`。
3. 提问：「文中有个格式为『校验串：……』的字符串，原样复述它，前后再各复述一句上下文。」

判读：老型号上下文窗口小，长文会被截断或回溯失败；旗舰型号应准确复述且上下文对得上。失败一次可能是截断策略问题，换埋点位置复测一次再下结论。

## 方法三：能力题同题对比（最硬的证据）

准备 2–3 道你已知标准答案的题，同一题分别发给「待测中转」和「参照组」（官方直连，或你确信可信的通道）：

- 一道带隐蔽 bug 的代码改错题（看定位精度）
- 一道多步逻辑/数学推理题（看过程是否跳步、结论是否对）
- 一道长文信息提取题（看漏不漏）

判读标准是**档次**不是逐字一致：同档 = 通过；稳定低一档（bug 定位不到、推理跳步错） = 红旗。样本至少 3 题、每题 1 次，避免单次随机性误判——温度设为 0 可进一步降噪。

## 方法四：报错信息漏馅

故意构造错误请求，看原始报错：
- 传一个不存在的模型名，看错误信息里列出的可用模型/内部名称
- 传超长输入，看报错提及的上下文上限数字

报错里出现的内部型号名、上下文上限与标牌对不上，是成本最低的实锤。但注意：有些站会统一包装报错，测不到不等于没问题，回到方法二、三。

## 记录模板

```
日期 / 时段：
标牌型号：          自报型号：
知识截止探针：      通过 / 不通过（题目与答案要点）
回溯题：            通过 / 失败（埋点位置、复述结果）
能力题对比：        同档 / 低一档（题数、参照组来源）
报错漏馅：          无 / 有（原文摘要，密钥已打码）
结论：              与标牌一致 / 存疑复测 / 红旗
```

## 自测通过标准

- 四种方法至少用了两种，且结论一致，才写「与标牌一致」
- 所有记录留具体题目与结果，不写「感觉是真的」
