# 中转站验真手册

中转站靠不靠谱，不靠口碑、不靠体感，靠对账。这本手册给你一套任何人可复现的检测方法：花 10 分钟、三步，就能把改名冒充、注入计费、缓存零命中这三种最常见的掺水手法抓出来。方法对任何中转站通用，包括你正在用的那家。

## 为什么需要验真：三种掺法速览

| 掺法 | 表现 | 损失方式 |
|---|---|---|
| 改名冒充 | 标牌写着新旗舰，底层是便宜的老型号（或别家的低端模型）改名顶替 | 你按旗舰价付费，拿到低一档的质量，项目返工 |
| 注入计费 | 每请求在你看不见的 system 层塞入几千到上万 token 的长 prompt | 倍率看着低，总账单贵 30%+，且神不知鬼不觉 |
| 缓存零命中 | 从不开启缓存，或缓存命中了但计费不返还 | 长会话、长文档场景成本翻倍，该省的全没省 |

共同点：**单看倍率都看不出来，全都能被账单和字段抓出来。**

总成本公式记住这一条：

```
真实成本 = 标价倍率 × (1 + 注入率) ÷ 缓存收益
```

## 三件套速查（5 分钟版）

| # | 测什么 | 怎么做 | 通过标准 |
|---|---|---|---|
| 1 | 空请求 | 发一句 `hi`，看这条请求的输入 token | 几十量级；出现四位数即异常 |
| 2 | 缓存连发 | 同一段长 prompt 连发两次，看第二次的 cached tokens | > 0 且计费明显下降 |
| 3 | 账单对账 | 本地数 token vs 控制台扣费（脚本：`scripts/token_count.py`） | 误差 <5% |

三项全过才算初步可信；任一红旗，先停用再说。完整流程见 [checklist.md](checklist.md)。

## 结果判读速览

**绿旗（可继续用）：** 空请求正常、缓存命中且返还计费、对账误差 <5%、模型题与官方同题同档、用量逐条可查。

**黄旗（复测再判）：** 缓存偶发未命中（单次）、高峰时段延迟大但账单正常、对账误差 5–10% 且能给出合理解释。

**红旗（停用留证）：** 空请求 token 四位数起、缓存长期 0、对账稳定多扣 >10%、模型题明显低一档、报错信息暴露真实型号与标牌不符、用量明细查不到逐条记录。

## 脚本说明

- `scripts/token_count.py`：本地 token 计数（优先 tiktoken，无依赖时给估算并明确标注），不联网、不需要任何密钥。
- `scripts/cache_probe.sh`：对 OpenAI 兼容接口连发两次同一长 prompt，打印两次的 usage 字段对比。站点和密钥只读环境变量（`RELAY_BASE_URL` / `RELAY_API_KEY` / `RELAY_MODEL`），脚本内不硬编码任何站点与密钥。

两个脚本都先看 `--help` / 文件头注释再运行。
